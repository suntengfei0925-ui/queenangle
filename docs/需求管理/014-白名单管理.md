# 白名单管理 PRD

## 1. 背景

当前小程序通过 `owner_whitelist` 控制谁可以进入系统。现有维护方式需要老板直接操作云数据库，不适合日常给员工或服务人开通、停用权限。

后续真实流程是：新人扫码进入小程序，如果不在启用白名单内，只能看到无权限页；新人可以复制自己的 `openid` 发给老板，也可以直接提交开通申请；老板在设置页进入白名单管理，审核申请或手动新增人员，并配置姓名后，对方才能使用小程序。

本期继续沿用 `openid` 白名单模式，不引入手机号授权、企业微信通讯录、多角色细分权限或微信消息通知。

## 2. 目标

- 无权限用户可以看到并复制自己的 `openid`。
- 无权限用户可以提交开通申请。
- 老板可以在小程序内查看待审核申请。
- 老板通过申请时必须填写姓名。
- 老板可以手动新增白名单人员。
- 老板可以编辑人员姓名、备注、启用状态、老板权限。
- 白名单增加 `isOwner` 字段，只有启用老板可以管理白名单。
- 老板权限变更、停用老板属于敏感操作，需要二次确认。
- 系统必须至少保留一个启用老板。

本期不做：

- 微信消息推送。
- 手机号授权登录。
- 企业微信通讯录身份。
- 多角色细分权限。
- 白名单硬删除。
- 白名单人员搜索。

## 3. 使用角色与可见性

### 3.1 新人

不在启用白名单中的微信用户，只能进入无权限页，不能查看业务数据。

可操作：

- 查看自己的 `openid`。
- 复制自己的 `openid`。
- 提交开通申请。

### 3.2 普通白名单人员

`enabled !== false` 且 `isOwner !== true` 的人员。

可操作：

- 正常登录并使用现有业务功能。
- 不可进入白名单管理。

### 3.3 老板

`enabled !== false` 且 `isOwner === true` 的人员。

可操作：

- 进入白名单管理。
- 查看、通过、拒绝开通申请。
- 手动新增白名单人员。
- 编辑人员姓名、备注、启停状态。
- 设置或取消老板权限。

## 4. 使用流程

### 4.1 新人申请

1. 新人扫码或打开小程序。
2. 系统发现当前 `openid` 不在启用白名单中。
3. 进入无权限页。
4. 页面展示当前 `openid`。
5. 新人点击“申请开通权限”。
6. 系统创建或恢复一条 `pending` 申请。
7. 页面提示“申请已提交，请联系老板审核”。
8. 页面继续保留“复制 openid”按钮。

### 4.2 老板审核

1. 老板进入设置页。
2. 点击“白名单管理”。
3. 页面展示待审核申请。
4. 老板点击某条申请的“通过”。
5. 系统要求老板填写姓名，可选备注。
6. 老板确认后，系统创建或恢复白名单人员：

```text
openid = 申请人的 openid
name = 老板填写的姓名
remark = 老板填写的备注
enabled = true
isOwner = false
```

7. 申请状态变为 `approved`。
8. 该用户下次重新进入小程序即可登录。

### 4.3 手动新增

1. 老板进入白名单管理。
2. 点击“新增人员”。
3. 输入 `openid`、姓名、备注。
4. 保存后新增普通人员：

```text
enabled = true
isOwner = false
```

手动新增入口不提供“是否老板”选项。如果要设置第二个老板，先新增为普通人员，再编辑该人员打开老板权限，并二次确认。

### 4.4 设置老板

1. 老板在已开通人员列表点击“编辑”。
2. 打开或关闭“老板权限”。
3. 系统弹出二次确认。
4. 后端校验成功后保存。

取消老板、停用老板同样需要二次确认，并且系统必须校验至少还剩一个启用老板。

## 5. 页面需求

### 5.1 设置页

新增入口：

```text
白名单管理
```

只有老板可见。普通白名单人员不展示该入口；如果通过路径直接访问，后端仍需拒绝。

### 5.2 无权限页

展示内容：

```text
当前微信用户未开通权限
请提交申请，或复制 openid 发给老板开通
当前 openid：xxx
```

按钮：

```text
申请开通权限
复制 openid
重新检查
```

提交申请后展示：

```text
申请已提交，请联系老板审核
```

### 5.3 白名单管理页

页面包含两块：

```text
待审核申请
已开通人员
```

待审核申请展示：

- `openid`
- 申请时间
- 状态
- 通过
- 拒绝

已开通人员展示：

- 姓名
- `openid`
- 备注
- 是否老板
- 启用/停用状态
- 编辑入口

### 5.4 通过申请表单

字段：

```text
姓名：必填
备注：可选
```

不允许未填写姓名时通过申请。

### 5.5 编辑人员表单

支持编辑：

- 姓名。
- 备注。
- 启用/停用。
- 是否老板。

不允许编辑 `openid`。如果 `openid` 录错，应停用原人员后重新新增。

以下操作需要二次确认：

- 设置老板。
- 取消老板。
- 停用老板。

## 6. 业务规则

### 6.1 老板权限

只有启用老板可以管理白名单。

上线前需要手动给当前老板的 `owner_whitelist` 记录添加：

```json
{
  "isOwner": true
}
```

系统不提供“没有老板时所有人临时可管理”的特殊逻辑。

### 6.2 申请规则

- 新人申请时不填写姓名，姓名由老板审核时填写。
- 同一个 `openid` 已有 `pending` 申请时，不重复创建，提示“申请已提交，请等待老板审核”。
- 同一个 `openid` 曾被拒绝后再次申请，将原申请状态改回 `pending`。
- 同一个 `openid` 已在白名单且启用时，再次申请提示已开通。
- 同一个 `openid` 已在白名单但停用时，再次申请通过后恢复原白名单记录，不新建重复人员。

### 6.3 审核规则

- 通过申请时必须填写姓名。
- 通过申请后创建或恢复白名单，默认启用，默认不是老板。
- 拒绝申请不需要填写拒绝原因。
- 已处理申请不能重复通过或重复拒绝。

### 6.4 手动新增规则

- `openid` 必填。
- 姓名必填。
- 备注可选。
- 新增人员默认启用，默认不是老板。
- `openid` 已存在时禁止新增，引导编辑原人员或通过申请恢复启用。

### 6.5 启停与删除规则

- 不做硬删除，只做停用。
- 停用后该人员不能登录系统。
- 停用不会影响历史记录中的创建人、服务人快照或作废记录追溯。

### 6.6 最后老板保护

系统必须至少保留一个启用老板。

不允许：

- 停用最后一个启用老板。
- 取消最后一个启用老板的老板身份。

允许设置别人为老板，但必须二次确认。

## 7. 数据需求

### 7.1 owner_whitelist

扩展现有集合：

```text
openid
name
enabled
isOwner
remark
createdAt
updatedAt
```

字段说明：

- `openid`：微信用户在当前小程序下的唯一标识。
- `name`：系统内展示姓名，用于服务人、记录展示等。
- `enabled`：是否允许登录。
- `isOwner`：是否老板，是否可管理白名单。
- `remark`：备注，例如岗位或说明。
- `createdAt`：创建时间。
- `updatedAt`：更新时间。

### 7.2 whitelist_applications

新增集合，用于保存无权限用户提交的开通申请。

```text
openid
status
createdAt
updatedAt
reviewedAt
reviewedByOpenid
```

`status` 支持：

```text
pending
approved
rejected
```

集合权限建议设置为“仅云函数可读写”。

## 8. 异常情况

- 重复申请：不创建重复记录，提示已提交。
- 已开通人员申请：提示已开通。
- 被拒绝人员再次申请：原申请回到 `pending`。
- 通过申请但未填写姓名：禁止提交。
- 手动新增未填写 `openid`：禁止保存。
- 手动新增未填写姓名：禁止保存。
- 手动新增 `openid` 已存在：禁止保存。
- 停用最后一个老板：禁止操作。
- 取消最后一个老板身份：禁止操作。
- 普通人员访问白名单管理：提示无权限。
- 白名单管理接口被普通人员直接调用：后端拒绝。
- `whitelist_applications` 集合未创建：接口提示先创建集合。

## 9. 权限与隐私

`openid` 属于内部权限识别信息，只在无权限页展示给本人，在白名单管理页展示给老板。

普通白名单人员不应看到其他人的 `openid`。

白名单管理会影响系统访问权限，所有管理接口必须由后端校验启用老板身份。

老板权限变更必须二次确认，防止误操作。

## 10. 验收标准

1. 设置页老板账号可以看到“白名单管理”入口。
2. 普通白名单人员看不到“白名单管理”入口。
3. 普通人员直接访问白名单管理页时，后端拒绝并提示无权限。
4. 无权限用户可以看到自己的 `openid`。
5. 无权限用户可以复制自己的 `openid`。
6. 无权限用户可以提交开通申请。
7. 重复提交申请不会产生重复待审核记录。
8. 被拒绝的人再次申请后，申请状态回到 `pending`。
9. 老板能看到待审核申请。
10. 老板通过申请时必须填写姓名。
11. 申请通过后，该用户进入启用白名单，默认不是老板。
12. 老板可以拒绝申请。
13. 老板可以手动新增 `openid + 姓名 + 备注`，新增人员默认启用且不是老板。
14. 手动新增入口不提供“是否老板”选项。
15. 老板可以编辑人员姓名和备注。
16. 老板可以停用人员。
17. 老板不能停用最后一个启用老板。
18. 老板可以设置第二个老板，操作前有二次确认。
19. 老板可以取消老板身份，但不能取消最后一个启用老板。
20. 已停用人员不能登录系统。
21. 不提供硬删除白名单人员能力。

## 11. 待确认问题

- 保留 `openid` 白名单模式。

- 老板权限使用 `isOwner` 字段控制。
- 上线前手动指定当前老板。
- 手动新增默认普通人员。

### 影响范围

- 页面：`miniprogram/pages/settings/index`、`miniprogram/pages/auth/no-permission`、新增 `miniprogram/pages/settings/whitelist`
- 云函数/API：`cloudfunctions/login`、`cloudfunctions/business`

- 第 1 步：扩展登录接口，返回 `isOwner`。
- 第 2 步：新增申请提交接口和无权限页申请按钮。
- 第 3 步：设置页根据 `isOwner` 展示白名单管理入口。
- 第 4 步：新增白名单管理页。
- 第 5 步：新增审核、手动新增、编辑人员接口。
- 第 6 步：实现老板权限二次确认和最后老板保护。
- 第 7 步：补数据库初始化文档和数据模型文档。
