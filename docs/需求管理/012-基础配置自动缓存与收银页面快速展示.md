# 基础配置自动缓存与收银页面快速展示 PRD

## 1. 背景

当前散客结账、会员结账、购卡/充值、新建会员补录次卡等页面，打开时会现场查询服务项目、次卡类型、充值档位，导致页面需要等待。

店内收银场景要求响应非常快，而这些基础配置低频变化，通常初始化后很久才改一次。因此不适合每次进入收银页面都现场等待云端配置返回。

## 2. 目标

- 让需要展示服务项目、次卡类型、充值档位的页面优先使用本地缓存，进入页面后尽快展示。
- 不做“部署”按钮，配置修改后自动刷新本机缓存。
- 小程序启动后静默预加载基础配置。
- 本需求不处理会员余额、会员折扣、会员剩余次卡等实时敏感数据缓存。

本需求暂不解决：

- 会员实时权益离线可用。
- 多台设备秒级同步配置。
- 配置变更审批或发布流程。

## 3. 使用角色与可见性

操作人是白名单老板/员工。

顾客可能在结账时看到页面，因此收银页面不能因加载配置长期空白。缓存机制不需要展示给用户感知，不需要在页面上显示“已同步”“缓存中”等状态。

会员余额、会员折扣、会员剩余次卡属于敏感实时权益数据，不得作为本地缓存长期使用依据。

## 4. 使用流程

1. 小程序启动后，系统静默拉取最新基础配置并写入本地缓存。
2. 进入散客结账、会员结账、购卡/充值、新建会员补录时，页面优先读取本地缓存并立即展示配置项。
3. 页面后台静默检查配置更新，如果发现新版本，自动刷新当前列表，不需要提示用户。
4. 设置页仍然从云端读取最新配置，保存成功后立即刷新本机缓存。
5. 真正提交结账、购卡、补录时，云端仍按数据库最新状态校验配置是否存在、是否启用。

## 5. 页面需求

### 散客结账

- 服务分类/服务项目优先从缓存展示。
- 如果本地无缓存，则走云端加载。
- 如果本地无缓存且网络失败，提示“配置加载失败，请重试”。

### 会员结账

- 服务分类/服务项目优先从缓存展示。
- 会员余额、会员折扣、会员剩余次卡仍现场查询。
- 页面可以先展示服务项目区，会员权益区等待会员详情返回后再显示。

### 购卡/充值

- 充值档位、次卡类型优先从缓存展示。
- 会员信息仍现场查询。
- 提交购卡时仍由云端按当前次卡类型校验价格、次数、启用状态。

### 新建会员补录

- 初始次卡类型优先从缓存展示。
- 如果没有缓存且网络失败，提示“次卡配置加载失败，请重试”。

### 设置页

- 设置页作为维护入口，仍然每次从云端加载最新配置。
- 修改服务项目、次卡类型、充值档位保存成功后，应立即刷新本机基础配置缓存。

## 6. 业务规则

- 可缓存的数据：服务分类、服务项目、次卡类型、充值档位。
- 不可缓存为准的数据：会员余额、会员折扣、会员剩余次卡、流水记录、历史记录。
- 如果本地有缓存，页面优先展示缓存，不等待云函数返回。
- 如果本地无缓存，则正常请求云端配置。
- 如果本地无缓存且网络失败，页面不能展示空项目，应明确提示重试。
- 如果缓存里有旧配置但提交时云端发现项目/次卡已停用或不存在，提交失败并提示“配置已更新，请重新选择”。
- 最终结账、购卡、补录提交仍以云端校验为准。

## 7. 数据需求

本地需要保存一份基础配置缓存，建议包含：

- 服务目录 `serviceCatalog`
- 启用次卡类型 `cardTypes`
- 充值档位 `rechargeTiers`
- 配置版本或更新时间 `version / updatedAt`
- 缓存写入时间 `cachedAt`

云端建议提供统一基础配置读取能力，减少多个页面分别查询：

- 当前启用服务目录
- 当前启用次卡类型
- 当前充值档位
- 配置版本或更新时间

历史记录不需要迁移，不影响已有流水。

## 8. 异常情况

- 首次使用或清空缓存后，第一次进入页面可能仍需等待加载。
- 缓存读取成功但后台刷新失败，不影响当前页面操作。
- 缓存为空且网络失败，提示“配置加载失败，请重试”。
- 缓存里有已停用项目，提交时由云端拦截，前端提示重新选择。
- 配置刷新过程中用户已选择项目，若刷新后项目不存在或停用，提交时仍以云端结果为准。

## 9. 权限与隐私

基础配置不属于敏感会员数据，但仍只对白名单用户可用。

会员实时权益数据不得本地长期缓存为业务依据，包括：

- 余额
- 当前折扣
- 剩余次卡
- 会员交易流水

## 10. 验收标准

1. 已有缓存时，打开散客结账页面，服务项目应立即展示，不等待云函数返回。
2. 会员结账页面中，服务项目先展示；会员余额和剩余次卡仍等待会员详情查询。
3. 修改服务项目并保存后，本机再次进入结账页能看到最新配置。
4. 另一台白名单手机不要求秒级同步，但下次启动或进入相关页面时会自动更新。
5. 缓存项目已被停用时，提交结账被云端拒绝，并提示重新选择。
6. 清空缓存且网络失败时，页面显示配置加载失败提示，不展示空项目。
7. 购卡/充值页面已有缓存时，充值档位和次卡类型能快速展示，会员信息仍现场查询。

## 11. 待确认问题

暂无。

当前结论：不做部署按钮，采用自动缓存与静默刷新。

## 开发交接版

### 影响范围

- 页面：散客结账、会员结账、购卡/充值、新建会员补录、设置页相关配置维护页面。
- 云函数/API：现有 `listServiceCatalog`、`listCardTypes`、`listRechargeTiers`，建议封装统一基础配置接口。
- 本地存储：新增基础配置缓存。
- 历史数据兼容：不影响历史记录。
- 权限与隐私：仍走现有白名单校验；会员实时权益不得作为缓存业务依据。

### 建议拆分

- 第 1 步：新增基础配置缓存工具，支持读取、写入、后台刷新。
- 第 2 步：小程序启动时静默预加载基础配置。
- 第 3 步：改造收银相关页面，优先读缓存，再后台刷新。
- 第 4 步：设置保存成功后刷新本机缓存。
- 第 5 步：补齐缓存缺失、配置过期、提交失败提示。

### 测试场景

- 正常流程：已有缓存打开结账页，项目立即展示。
- 首次流程：无缓存时正常加载，成功后写入缓存。
- 配置修改：设置页修改后，本机缓存更新。
- 多设备流程：另一台白名单手机下次启动或进入相关页面时自动更新。
- 过期配置：缓存里有停用项目，提交时云端拒绝。
- 会员数据：会员余额、折扣、剩余次卡仍然现场查询，不使用缓存。
