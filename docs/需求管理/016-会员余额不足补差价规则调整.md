# 会员余额不足补差价规则调整 PRD

## 1. 背景

当前会员结账在余额不足时，按“整单折后金额 - 当前余额”计算补差价。这个规则对顾客比较友好，但对店铺来说，相当于余额不足的那一部分仍然继续享受会员折扣，店铺收益被压低。

新规则希望更平衡：会员现有余额仍然按会员折扣使用，但只能覆盖它能够覆盖的那部分原价服务；余额覆盖不了的部分，按原价补差。这样比整单取消折扣更容易让顾客接受，也比只补折后差价更保护店铺收益。

## 2. 目标

- 调整会员余额不足且客户不充值时的补差价计算规则。
- 让页面清楚展示“余额按折扣抵扣了多少原价服务”。
- 本单结算金额按 `余额支付 + 补差价` 展示，更符合顾客心理预期。
- 补差价属于实际收款，必须记录支付方式。
- 会员余额扣到 0 后，继续清空会员当前折扣。

不处理：

- 次卡扣减规则。
- 今日流水展示大改。
- 结账草稿暂存。
- 系统内手动调整补差金额，老板线下实际收款调整暂不进入本需求。

## 3. 适用范围

适用于会员结账中的普通服务项目。

不适用于：

- 散客消费。
- 纯次卡结账。
- 会员充值。
- 购卡。
- 历史记录重新计算。

## 4. 使用角色与可见性

主要操作者为老板或店内白名单人员。

会员结账时，顾客可能会和老板一起查看手机页面并完成签字确认。因此余额、折扣、补差价和本单结算金额需要用清楚、可解释的方式展示，避免顾客误以为系统多收或少收。

本需求不新增权限规则，仍沿用现有白名单登录和会员结账权限。

## 5. 使用流程

1. 老板进入会员结账页。
2. 选择普通服务项目并填写原价。
3. 系统根据会员当前余额和当前折扣自动计算。
4. 如果余额足够支付整单会员价，按原有逻辑结账。
5. 如果余额不足，页面展示余额不足说明，并提供：
   - `去充值`
   - `继续补差结账`
6. 如果选择去充值，进入充值流程；充值完成后重新进入会员结账并重新选择项目，不保留本次草稿。
7. 如果继续补差结账，必须选择补差价支付方式。
8. 客户确认并签字后，系统保存记录、扣减余额、记录补差收款。

## 6. 页面需求

### 6.1 会员结账页

会员结账页余额不足时，需要展示：

- 项目原价合计
- 当前折扣
- 整单会员价
- 当前余额
- 余额可抵扣的原价服务金额
- 补差价
- 本单结算金额
- 消费后余额

建议说明文案：

```text
当前余额 ¥300.00 按 8 折可抵扣原价 ¥375.00，剩余原价 ¥125.00 需补差。
```

按钮：

```text
去充值
继续补差结账
```

### 6.2 客户确认弹窗

客户确认弹窗需要展示补差解释，避免顾客只看到“整单会员价”和“本单结算金额”不一致。

余额不足场景建议展示：

```text
项目原价：¥500.00
当前折扣：8 折
整单会员价：¥400.00
当前余额：¥300.00
余额可抵扣原价：¥375.00
补差价：¥125.00
本单结算金额：¥425.00
消费后余额：¥0.00
```

其中“本单结算金额”按 `余额支付 + 补差价` 展示，例如 `300 + 125 = 425`。

### 6.3 记录详情页

记录详情页需要展示补差解释，方便后续查账和向客户解释。

示例：

```text
余额 ¥300.00 按 8 折抵扣原价 ¥375.00，剩余原价 ¥125.00 已补差。
```

今日流水和记录列表暂不调整，未来另起需求统一改造。

## 7. 业务规则

### 7.1 正常余额足够

示例：

```text
原价 500
折扣 8 折
余额 1000
整单会员价 = 500 × 0.8 = 400
余额支付 = 400
补差价 = 0
本单结算金额 = 400
```

余额足够时，仍按原有会员价扣余额，不触发余额不足补差规则。

### 7.2 余额不足且不充值

公式：

```text
折扣率 = 当前折扣 / 10
余额可覆盖原价 = 当前余额 ÷ 折扣率
补差价 = 整单原价 - 余额可覆盖原价
本单结算金额 = 当前余额 + 补差价
```

示例：

```text
原价 500
折扣 8 折
余额 300

余额可覆盖原价 = 300 ÷ 0.8 = 375
补差价 = 500 - 375 = 125
余额支付 = 300
本单结算金额 = 300 + 125 = 425
消费后余额 = 0
```

### 7.3 无折扣或 10 折

无折扣、10 折时，等同于普通原价补差。

```text
原价 500
余额 300
补差价 = 200
本单结算金额 = 500
```

### 7.4 取整规则

补差相关计算保留到角，按四舍五入处理。

系统内部仍可按分存储，但计算结果最小业务粒度为 0.1 元。页面展示可沿用现有金额格式，例如 `¥125.00` 或 `¥88.90`。

如果老板实际收款时需要再做微调，由老板在线下收款时自行调整；本需求暂不增加系统内手动改补差价功能。

### 7.5 补差支付

补差价是实际现金类收款，不是余额扣减，也不是次卡扣减。

当 `补差价 > 0` 时：

- 必须选择补差价支付方式。
- 记录中保存补差价金额。
- 记录中保存补差价支付方式。
- 会员余额扣到 0。
- 当前折扣清空为“无折扣”。

### 7.6 充值后重新计算

如果客户看到余额不足后选择先充值，本次结账不保存草稿。

充值完成后，老板重新进入会员结账页并重新选择项目。系统按充值后的最新余额和最新折扣重新计算本单，不再使用充值前的余额不足补差结果。

## 8. 数据需求

会员结账记录需要保留现有字段，并建议新增补差规则快照：

```text
balancePayCent              余额支付金额
extraPayCent                补差价金额
actualReceivedCent          实际额外收款金额，等于补差价
balanceCoveredOriginalCent  余额按折扣可覆盖的原价金额
settlementAmountCent        本单结算金额 = 余额支付 + 补差价
shortageExtraPayRule        补差规则版本，例如 balance_discount_cover_original_v1
```

同时签字快照中应包含：

```text
整单原价
当前折扣
整单会员价
余额支付
余额可覆盖原价
补差价
本单结算金额
消费后余额
补差价支付方式
```

这些字段用于记录详情展示、签字校验、未来统计和后续查账。

## 9. 异常情况

- 客户选择去充值：不保存当前结账草稿，充值后重新进入结账页选择项目。
- 充值后再结账：按充值后的最新余额和最新折扣重新计算。
- 余额为 0：不触发会员余额抵扣，按当前已有无余额逻辑处理。
- 纯次卡结账：不展示补差价规则。
- 客户签字后修改项目、金额、支付方式或备注：签字失效，必须重新确认和签字。
- 作废会员结账记录：恢复结账前余额和折扣状态。
- 补差价大于 0 但未选择支付方式：不允许提交。
- 云函数保存时需要重新计算金额，不能只信任前端传入的补差结果。

## 10. 权限与隐私

本需求不新增权限规则。

会员结账仍沿用当前白名单登录和业务权限控制。

客户确认弹窗和签字流程会展示会员余额、折扣和补差价，因此这些内容只在结账确认场景展示，不额外扩大到首页、历史列表或其他公开页面。

记录详情页展示补差解释，用于老板查账和售后解释。

## 11. 验收标准

1. 原价 500、8 折、余额 300 时，余额支付为 300，补差价为 125，本单结算金额为 425。
2. 余额不足时，页面展示“余额按折扣可抵扣的原价金额”说明。
3. 余额不足时，可以选择去充值；去充值不保留当前结账草稿。
4. 余额不足并继续结账时，必须选择补差价支付方式。
5. 余额足够时，仍按原有会员价扣余额，不产生补差价。
6. 无折扣或 10 折时，余额不足按原价补差。
7. 纯次卡结账不受影响，不展示补差说明。
8. 结账成功后余额为 0 时，会员折扣清空。
9. 记录详情能看到补差解释。
10. 作废记录后，余额和折扣恢复到结账前状态。
11. 客户签字确认内容中包含余额可覆盖原价、补差价和本单结算金额。
12. 签字后修改金额或支付方式，原签字失效，需要重新签字。

## 12. 待确认问题

暂无。

当前结论：

- 余额不足且客户不充值时，余额按当前折扣抵扣可覆盖的原价服务。
- 未覆盖部分按原价补差。
- 补差相关计算保留到角，按四舍五入处理。
- 补差价是实际收款，必须记录支付方式。
- 不做结账草稿暂存。
- 今日流水暂不调整。

### 建议拆分

- 第 1 步：抽出会员结账金额计算规则，前端展示和云函数保存必须使用同一业务口径。
- 第 2 步：前端会员结账页增加余额不足说明、去充值入口、继续补差结账路径。
- 第 3 步：余额不足时增加 `余额可覆盖原价`、`本单结算金额` 等展示字段。
- 第 4 步：调整确认弹窗和签字快照，加入余额可覆盖原价、本单结算金额、补差解释。
- 第 5 步：云函数 `createMemberCheckout` 使用新规则重新计算并保存，不能只信任前端金额。
- 第 6 步：记录详情展示补差解释。
- 第 7 步：回归作废逻辑，确保余额和折扣恢复正确。

### 测试场景

正常流程：

- `500 / 8折 / 余额300`：余额可覆盖原价 375，补差 125，结算 425。
- `500 / 8折 / 余额400`：余额支付 400，补差 0，结算 400。
- `500 / 无折扣 / 余额300`：补差 200，结算 500。
- `200 / 9折 / 余额100`：按保留到角规则计算并展示。
- 余额不足后选择继续补差结账，必须选择补差支付方式后才能签字提交。
- 余额不足后选择去充值，充值完成后重新进入结账并按新余额、新折扣计算。

异常流程：

- 纯次卡结账不展示补差说明。
- 补差价大于 0 但未选择支付方式，提交失败并提示选择支付方式。
- 签字后修改项目、金额、支付方式或备注，必须重新签字。
- 记录保存失败时，不扣余额、不生成有效记录。

数据回归：

- 记录保存后包含余额支付、补差价、实际额外收款。
- 记录保存后包含余额可覆盖原价和本单结算金额快照。
- 签字快照哈希仍能校验当前确认内容。
- 作废记录后，余额和折扣恢复到结账前状态。
- 历史记录不重新计算。
