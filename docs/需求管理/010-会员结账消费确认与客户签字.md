# 会员结账消费确认与客户签字 PRD

## 1. 背景

会员结账会减少会员权益，例如扣减会员余额或扣减次卡次数。真实门店场景中，老板选择会员后，会员和老板通常一起看手机完成结账，因此客户需要清楚确认本次消费内容、折扣、扣款和结账后余额。

散客消费是当场付款结清，不涉及会员权益变化，本次不需要确认签字。

## 2. 目标

在会员结账点击“完成结账”时，增加客户确认和签字流程。

目标包括：

- 会员结账必须先展示消费确认弹窗。
- 客户确认后进入横屏签字页。
- 客户签字后回到会员结账页，显示签名缩略图。
- 有有效签名后，再次点击“完成结账”才真正保存记录。
- 签名和客户确认快照需要保存到会员结账记录中。
- 散客消费不受影响。

本次不处理：

- 散客消费签字。
- 余额归零导致折扣清空的单独确认设计。
- 会员结账之外的其他业务签字，例如充值、购卡。

## 3. 使用角色与可见性

主要操作者为老板，确认和签字人为客户本人。

会员结账时，老板和客户会同时看到手机界面。确认弹窗需要让客户清楚理解本次会员权益减少情况，包括余额变化、折扣后金额、补差价和次卡扣减。

签名属于客户确认凭证，应保存到本次会员结账记录中。历史列表不展示签名，记录详情页可查看签名。

## 4. 使用流程

完整流程：

```text
老板点击完成结账
-> 弹出消费确认弹窗
-> 客户点击“确认并签字”
-> 进入横屏签字页
-> 客户签字并点击“确认签字”
-> 回到会员结账页，显示签名缩略图
-> 老板再次点击“完成结账”
-> 系统保存会员结账记录并扣减权益
```

如果客户点击“返回修改”，或签字页返回，则不保存记录、不扣余额、不扣次卡，回到会员结账页并保留已选内容。

签字完成后不立即扣减会员权益。只有最终再次点击“完成结账”并提交成功后，才保存记录、扣减余额或次卡次数。

## 5. 页面需求

### 5.1 消费确认弹窗

弹窗标题：

```text
请确认本次会员结账
```

按钮：

```text
返回修改
确认并签字
```

弹窗为自定义居中弹窗，视觉上接近系统弹窗，面积约页面 50%。不建议使用纯 `wx.showModal`，因为确认内容需要不同颜色、字号和区块层级。

弹窗内容分三块：

- 余额变化：期初余额、余额支付、消费后余额。
- 消费金额：项目原价、当前折扣、折后金额、补差价和支付方式。
- 次卡变化：次卡名称、扣减次数、使用后剩余次数。

金额和变化值不能全部同字号、同颜色。余额减少、扣次卡等变化应使用强调色、负号或独立色块，让客户一眼看出变化。

### 5.2 确认弹窗内容

存在普通收费项目时，展示：

```text
期初余额
项目明细与单项原价
项目原价合计
当前折扣
折后金额
余额支付
补差价
补差价支付方式
消费后余额
```

存在次卡使用时，逐张展示：

```text
次卡名称
扣 1 次
使用后剩余 N 次
```

纯次卡场景不展示普通项目金额区，只展示次卡扣减明细。

### 5.3 签字页

签字页强制横屏体验。老板可以提醒客户横向拿手机。

页面只展示：

```text
请客户签字确认
签字区域
清空重签
确认签字
```

签字页不展示消费摘要。客户在进入签字页前已经通过确认弹窗看过确认内容。

客户至少需要有一笔签字轨迹，空白签字不能确认。

### 5.4 签名预览

签字完成后返回会员结账页，在“完成结账”按钮上方展示：

```text
客户已签字
签名缩略图
重新签字
```

点击“重新签字”时，需要重新弹出消费确认弹窗，再进入签字页。

### 5.5 提交按钮行为

第一次点击“完成结账”：

- 如果没有有效签名，弹出消费确认弹窗。
- 客户确认后进入签字页。

签字完成后再次点击“完成结账”：

- 如果签名有效且内容未变化，直接提交保存记录。
- 如果签名不存在或已失效，重新进入确认和签字流程。

## 6. 业务规则

### 6.1 适用范围

所有会员结账都需要确认和签字。

散客消费不需要确认和签字。

本次不单独设计“余额归零导致折扣清空”的确认规则，后续另起需求。

### 6.2 签名有效性

签名绑定的是当时那一版确认内容。

如果签字后老板修改了以下任意影响记录内容的信息，原签名失效，必须重新确认并签字：

- 服务项目
- 项目金额
- 次卡选择
- 支付方式
- 备注
- 其他会影响本次记录内容或客户确认快照的字段

有有效签名且内容未变化时，再次点击“完成结账”直接提交。

没有签名或签名失效时，点击“完成结账”先进入确认弹窗和签字流程。

### 6.3 保存时机

签字完成后不立即扣余额、不扣次卡、不生成正式记录。

最终点击“完成结账”提交成功后，才保存记录、上传或关联签名，并扣减会员权益。

签名图片建议最终提交时再上传并关联记录，避免客户签字后老板取消结账时产生无用文件。

### 6.4 作废规则

作废记录时，签名保留。

作废只是记录状态变为作废，不应删除客户当时确认过的凭证。

## 7. 数据需求

### 7.1 records

会员结账记录需要新增签字相关字段：

```text
signatureFileId
signatureSignedAt
signatureSnapshot
signatureSnapshotHash
```

字段说明：

- `signatureFileId`：签名图片云存储文件 ID。
- `signatureSignedAt`：客户确认签字时间。
- `signatureSnapshot`：客户签字时看到的确认内容快照。
- `signatureSnapshotHash`：确认快照校验值，用于判断签名是否匹配当前结账内容。

### 7.2 signatureSnapshot

`signatureSnapshot` 保存客户签字时看到的确认内容，包括：

```text
会员信息
项目明细
期初余额
当前折扣
折后金额
余额支付
补差价与支付方式
消费后余额
次卡扣减明细
备注
```

次卡扣减明细示例：

```json
[
  {
    "cardTypeId": "card_type_id",
    "cardName": "手部护理10次卡",
    "useTimes": 1,
    "remainingTimesBefore": 8,
    "remainingTimesAfter": 7
  }
]
```

项目明细示例：

```json
[
  {
    "categoryName": "美睫",
    "serviceName": "单根",
    "originalAmountCent": 12800
  }
]
```

### 7.3 签名图片

签名图片建议保存到云存储。

记录中只保存文件 ID，不把大图片直接写入记录字段。

## 8. 记录展示

记录详情页底部展示：

```text
客户签名
签字时间
签名图片
```

历史列表不展示签名。

记录详情页继续展示当前记录明细，不需要额外把 `signatureSnapshot` 完整展开成一大块，避免页面重复。

`signatureSnapshot` 主要用于审计和校验，不作为默认展示内容。

## 9. 异常情况

- 客户取消确认：回到会员结账页，不保存记录，不扣减权益。
- 客户在签字页返回：回到会员结账页，不保存记录，不扣减权益。
- 客户未签字就确认：提示“请先完成签字”。
- 签字后修改结账内容：签名失效，要求重新确认和签字。
- 签名上传失败：不保存结账记录，不扣减会员权益。
- 记录保存失败：不扣减会员权益，保留页面内容方便重试。
- 重复点击提交：按钮应 loading 或禁用，避免重复记录。

## 10. 权限与隐私

本次不新增员工和老板权限区分，沿用当前 owner 校验。

签名属于客户确认凭证，应仅在记录详情页展示，不出现在历史列表和首页列表中。

签名图片和确认快照应与会员结账记录一同保留。作废记录时不删除签名。

## 11. 验收标准

1. 散客消费点击保存时不出现签字流程。
2. 会员结账第一次点击“完成结账”时出现消费确认弹窗。
3. 消费确认弹窗展示余额变化、消费金额和次卡变化，并通过颜色、字号或区块突出变化。
4. 客户点击“确认并签字”后进入横屏签字页。
5. 空白签字不能确认，提示“请先完成签字”。
6. 签字完成后回到结账页，并显示签名缩略图。
7. 签字后修改项目、金额、次卡、支付方式或备注，签名失效，需要重新确认和签字。
8. 有有效签名后再次点击“完成结账”，才真正保存记录并扣减权益。
9. 记录详情页可以查看客户签名和签字时间。
10. 作废记录后，签名仍保留。

### 建议拆分

- 第 1 步：设计确认快照结构和 `signatureSnapshotHash` 规则。
- 第 2 步：会员结账页增加确认弹窗、签名状态和签名失效逻辑。
- 第 3 步：新增横屏签字页，支持清空、确认、空签校验。
- 第 4 步：签字完成后回到会员结账页并展示签名缩略图。
- 第 5 步：最终提交时上传签名并调用 `createMemberCheckout`。
- 第 6 步：后端校验签名字段并写入会员结账记录。
- 第 7 步：记录详情页展示客户签名和签字时间。

### 测试场景

正常流程：

- 纯次卡会员结账签字后提交。
- 普通项目会员结账签字后提交。
- 次卡加普通项目混合结账签字后提交。
- 有有效签名且内容未变化时，再点“完成结账”直接提交。

异常流程：

- 客户取消确认后不生成记录。
- 客户返回签字页后不生成记录。
- 空签不能确认。
- 签名上传失败时不生成记录、不扣减权益。
- 重复点击提交不会生成重复记录。

数据回归：

- 签字后修改内容，必须重签。
- 记录保存后包含 `signatureFileId`、`signatureSignedAt`、`signatureSnapshot`、`signatureSnapshotHash`。
- 记录详情使用签名文件展示客户签名。
- 作废记录后签名仍可查看。
- 散客消费流程不受影响。
