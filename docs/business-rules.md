# 业务规则落地

## 会员充值

- 选择充值档位。
- 会员余额增加档位金额。
- 会员当前折扣更新为本次档位折扣。
- 生成充值记录和余额流水。

## 老会员新建补录

- 补录只允许在新建会员时填写，编辑已有会员时不展示补录入口。
- 会员生日只保存月日，不保存年份，生日可在会员资料中继续编辑。
- 填写非默认余额、非默认折扣、来源本子加页码、或任意初始次卡时，会员来源为 `imported`；否则为 `normal`。
- 补录导入时写入会员初始余额、初始折扣和初始次卡，并生成 `member_initial_balance` 记录与 `initial_balance` 余额流水。
- 页面不提供补录备注输入；系统自动生成补录备注，填写本子页码时格式为 `老会员补录；来源：本子2；页码：15`，否则为 `老会员补录`。
- 初始余额可以为 0，补录导入时仍生成余额流水。
- 初始余额不计入今日实收、充值收入、消费金额、余额支付和收款方式统计。
- 初始次卡只表示历史权益迁移，写入会员 `cardBalances`、`member_initial_balance.cardItems[]` 和 `initial_card` 次卡流水，不生成 `card_purchase`，不计入今日实收、充值收入或购卡收入。
- 初始次卡只能从启用的次卡类型中选择，同一种次卡不可重复补录；剩余次数必须是正整数，允许超过次卡类型的默认次数。
- 来源本子和页码必须同时填写；页码必须是正整数。
- 初始折扣按折数保存，必须大于 0 且小于 10；未填写时保存为 `null`，展示为“无折扣”。

## 会员消费

消费必须选择至少一个服务项目。每个项目保存分类、项目名称和单项原价快照，整单原价为所有单项原价之和。

余额大于 0 且存在当前折扣时：

```text
消费金额 = 整单原价 * 折扣 / 10
余额支付 = min(当前余额, 消费金额)
补差价 = 消费金额 - 余额支付
```

余额为 0 时：

```text
消费金额 = 整单原价
余额支付 = 0
补差价 = 整单原价
```

余额扣到 0 后：

```text
currentDiscount = null
currentDiscountLabel = 无折扣
```

## 会员结账

- 会员结账可同时选择可用次卡和普通服务项目，至少需要选择其中一项。
- 每张选中的次卡本次固定扣 1 次，扣减后不得小于 0。
- 纯次卡结账不需要选择支付方式，不计入实收、消费金额、余额支付、充值或次卡购买收入。
- 包含普通项目时，普通项目金额、会员余额支付、补差价和折扣规则沿用会员消费逻辑；次卡不参与金额计算。
- 一次会员结账只生成一条 `member_checkout` 记录；作废时整条记录统一回放余额、折扣和次卡次数。

## 散客消费

- 不绑定会员。
- 不影响余额和次卡。
- 必须选择至少一个服务项目，每个项目单独填写原价。
- 整单原价为所有服务项目单项原价之和。
- 实收金额等于本次新收款。

## 服务分类与服务项目

- 服务分类可新增、编辑、启用或停用。
- 新增服务分类时，自动创建一个启用状态的“其他”服务项目。
- 服务项目归属于服务分类，只维护名称、备注和启用状态，不维护固定价格。
- 同一分类下服务项目名称不允许重复，不同分类下允许重复。
- 结账选择服务项目时，同分类下项目按有效消费次数倒序排列；“其他”始终排在该分类最后。

## 次卡购买

- 增加会员名下对应次卡剩余次数。
- 生成购买记录和次卡流水。

## 次卡核销

- 默认核销 1 次。
- 不允许核销超过剩余次数。
- 不产生消费金额和实收金额。

## 作废

- 记录不硬删除，只把状态改为 `void`。
- 今日流水统计只计算 `active` 记录。
- 有会员状态变更的记录会按有效记录重放会员状态。
- `member_initial_balance` 作为会员初始余额、初始折扣和初始次卡参与重放，作废后续充值或消费时会保留补录初始状态。
